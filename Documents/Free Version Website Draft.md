## Roadmap Nexus Free Version Website Draft

This draft is based on:

- `Roadmap-Nexus-Template.md`
- `Roadmap Nexus – Market, Product, and Website Blueprint (2026).md`

The goal here is not the Pro website.

This is the website direction for the `free/open-source core` only, so the structure should stay:

- clean
- developer-first
- credible
- minimal
- product-led

It should not feel overbuilt, premium-enterprise, or feature-heavy.

## What The Free Version Is

Roadmap Nexus Free should present itself as:

- an open-source core
- a self-hostable Next.js starter
- a single-project setup
- a product shell for roadmap, changelog, and feedback

It should communicate:

- you can launch fast
- you own the code
- you avoid recurring roadmap SaaS pricing
- you can later upgrade to a more complete Pro layer

It should not imply that free includes:

- multi-project support
- advanced branding
- premium themes
- heavy integrations
- advanced analytics
- enterprise workflows

## Recommended Website Structure

For the free version, keep the website to `8 sections`.

### 1. Hero

Contains:

- product name: `Roadmap Nexus`
- one clear headline
- one supporting subheadline
- primary CTA: `View Demo`
- secondary CTA: `View GitHub`
- product visual showing roadmap, changelog, and feedback together
- short trust strip such as:
  - `Open Source`
  - `Self-Hostable`
  - `Next.js`
  - `Single-Project Core`

Purpose:

- explain the product immediately
- establish that it is a real developer product, not a concept

### 2. What It Is

Contains:

- short introduction to the 3 core modules:
  - `Public Roadmap`
  - `Changelog`
  - `Feedback Board`
- one small visual, icon, or micro-preview for each
- one short line clarifying that this is the free core starter

Purpose:

- make the scope obvious
- stop the site from feeling vague

### 3. Product Preview

Contains:

- preview of roadmap page
- preview of changelog page
- preview of feedback board
- can be shown as tabs, panels, or stacked views

Purpose:

- prove there is an actual product
- make the UI the main selling asset

### 4. Why It Exists

Contains:

- 3 to 4 practical reasons such as:
  - avoid recurring roadmap SaaS fees
  - own your code and data
  - launch faster
  - build inside your own Next.js stack

Purpose:

- connect the product to a real pain point
- justify why someone would use this instead of a hosted tool

### 5. What Free Includes

Contains:

- list of free-version inclusions:
  - public roadmap
  - public changelog
  - feedback board
  - basic admin management
  - single-project setup
  - basic docs
- list of what is not included in free:
  - multi-project support
  - premium themes
  - advanced integrations
  - polished Pro-only UX extras

Purpose:

- set expectations clearly
- create a clean boundary between free and future paid version

### 6. Developer Stack

Contains:

- stack row:
  - `Next.js`
  - `TypeScript`
  - `Tailwind`
  - `Prisma`
  - `PostgreSQL`
- short copy about self-hosting and developer control
- optional code/config style visual

Purpose:

- appeal directly to the real user
- reinforce that this is a serious starter, not just a marketing page

### 7. Docs Preview

Contains:

- docs-style layout preview
- simple sections such as:
  - `Install`
  - `Configure`
  - `Run Locally`
  - `Deploy`
- clean sidebar + content layout if needed

Purpose:

- show implementation credibility
- increase trust in the template quality

### 8. CTA + Footer

Contains:

- final CTA block
  - `View Demo`
  - `Open GitHub`
- short line explaining that the free core is open source and expandable
- footer links:
  - `GitHub`
  - `Docs`
  - `Demo`
  - `License`

Purpose:

- give the page a clean close
- direct users to the actual next steps

## What The Website Needs To Communicate

The free-version website must communicate:

- this is real
- this is useful
- this is open-source
- this is self-hostable
- this is minimal but solid
- this is the core layer, not the full paid edition

## Tone And Visual Rules For TasteSkill

The free version should feel:

- clean
- developer-first
- restrained
- sharp
- product-led

Focus on:

- strong typography
- clear hierarchy
- product previews over decorative visuals
- open-source credibility
- simple information density

Avoid:

- fake testimonials
- bloated pricing logic
- enterprise dashboard energy
- aggressive SaaS marketing sections
- feature overload
- flashy gradients and generic AI aesthetics

## Best First Image Set

If generating only the first TasteSkill batch, start with:

1. Hero
2. What It Is
3. Product Preview
4. What Free Includes
5. Docs Preview
6. CTA + Footer

That is enough to lock the website direction for the free version before building the rest.
